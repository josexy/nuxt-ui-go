# Internationalization

NuxtUI Go ships with English (`en`) and Simplified Chinese (`zh-Hans`). Component messages such as Clear, Close, pagination labels, and empty states follow the window's language. Your app translates the text it passes in, such as titles, menu labels, and business data.

This page covers [setting up your app](#setting-up-your-app), [what gets translated](#what-gets-translated), and [overriding built-in messages](#overriding-built-in-messages).

## Setting up your app

### Declare supported languages

If your app has no translation catalog of its own, add this before creating any window:

```go
mygo.App.SetLanguages(nui.SupportedLocales()...)
```

`SupportedLocales()` returns a new `[]string{"en", "zh-Hans"}` slice. If your app already registers its own catalog with MyGo's `i18n.Register`, keep declaring your app's languages as before. **Do not call `i18n.Register` on the library's catalog.**

The library embeds the catalogs in `ui/locales/` and loads them with MyGo's `i18n.NewLibraryCatalog` under the `nuxtui` namespace. Each component reads the language from the current window's `c.Locale()`. The library keeps no global language state of its own and never changes your app's list of supported languages.

### Switch languages

Call one of these from a UI action, such as a button click:

```go
mygo.App.SetLocale("zh-Hans") // Simplified Chinese
mygo.App.SetLocale("en")      // English
mygo.App.SetLocale("")        // Follow the system
```

MyGo refreshes every window, updates native controls, and saves the preference. You usually do not need to force a language at startup: MyGo chooses one from the app's supported languages, the user's saved choice, and the system language.

For automated tests, set the environment variable `MYGO_LOCALE=en` to pin the language without saving a preference. The Gallery calls `mygo.App.SetLanguages("en")` to use English only; apps that need both languages can set up as shown above.

## What gets translated

### Text the components translate

| Type | Examples |
| --- | --- |
| Action names and accessible names | Clear, Close, Remove, Cancel, Retry, Previous page, Next page, Increment and decrement |
| Default prompts and states | Search, Create option, Loading, empty lists, empty tables, upload status, file rule errors |
| Built-in input errors | Generic invalid value, and number, date, and time parse errors |
| Dates and native control text | Calendar months, years, and weekdays; ColorPicker channel names; editor system menus |

Built-in errors that are already stored are reformatted when the language changes. A language change does not count as a form edit, and components keep input drafts, selections, and business values.

### Text your app translates

Text you pass explicitly, such as `Label`, `Description`, `Placeholder`, `ErrorMessage`, `EmptyText`, `ChooseLabel`, and `CloseLabel`, is displayed as is. Your app also translates business validation errors, server errors, Toast titles, menu items, table data, and Timeline dates.

Built-in errors from upload rules keep following the language. If your app rewrites `UploadFile.Error`, the new value is treated as business text and kept as is.

### Defaults that are easy to confuse

| Situation | Message and key |
| --- | --- |
| The list has no data | `noData`: No data / 没有数据 |
| There is a query but nothing matches | `noMatch`: No matching data / 没有匹配的数据 |
| PinInput's default accessible name | `pinCharacters` in text mode and `pinDigits` in numeric mode; the count follows `Length` |
| Creating an option; remaining count in an avatar group | `createItem` and `morePeople` |

For example, a 5-cell PinInput is named `5 characters` / `5 个字符`, or `5 digits` / `5 位数字` in numeric mode. This is the editor's accessible name; the placeholder shown in each cell still comes from `Placeholder`. An explicit `Label` or FormField label takes precedence.

The older empty-state keys `noOptions`, `noResultsFound`, `noResults`, `noRecords`, and `noItems` are still supported. If your app already overrides one of them, the matching component keeps using your override. Enum values, icons, separators, and the percent sign (which is the same in both languages) have no translation keys.

## Overriding built-in messages

To override a component message, add a key with the `nuxtui.` prefix to **your app's own MyGo catalog**. For example:

Your app's `en.json`:

```json
{
  "@@locale": "en",
  "nuxtui.noMatch": "Nothing matched",
  "nuxtui.clearNamed": "Clear {name}"
}
```

Your app's `zh-Hans.json`:

```json
{
  "@@locale": "zh-Hans",
  "nuxtui.noMatch": "没有匹配的内容",
  "nuxtui.clearNamed": "清空{name}"
}
```

Connect your catalog the usual MyGo way, with `i18n.NewCatalog` and `i18n.Register`. Keys you do not override use the library's translations, and languages the library does not support fall back to English.

All keys are listed in the [English catalog](../ui/locales/en.json) and the [Simplified Chinese catalog](../ui/locales/zh-Hans.json). When you override a message with parameters, keep the parameter names and types, such as `{name}` above. Use the ICU plural rules that MyGo supports for counts.

## Formats and language coverage

### Dates and times

Calendar uses MyGo's date formatting for months, years, and weekdays. InputDate and InputTime use MyGo's CLDR locale formats to order the date or time segments, choose separators, and show AM/PM text in the current language. Digits are always ASCII, for both input and display.

`DateInputState.Text` always holds an ISO date draft. `TimeInputState.Text` holds a fixed-format numeric time with an AM/PM draft. This storage format is independent of the on-screen segment order, so changing the language keeps the business value, the draft, and field focus. Your app still sets the first day of the week with `WeekStart`.

Segment names use the keys `dateYear`, `dateMonth`, `dateDay`, `timeHour`, `timeMinute`, `timeSecond`, and `timePeriod`. Placeholders use the same keys with a `Placeholder` suffix.

### Not yet supported

Traditional Chinese, full locale-aware number input, and alternative calendars are not built in. The full RTL and screen reader experience has not been fully verified. For platform support and IME issues, see [Compatibility and known limitations](compatibility.md).
