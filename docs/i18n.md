# 国际化：语言切换与文案覆盖

NuxtUI Go 内置英文（`en`）和简体中文（`zh-Hans`）。清空、关闭、分页、空状态等组件文案会随窗口语言切换；你传入的标题、菜单文字和业务数据由应用负责翻译。

本文依次介绍[应用接入](#应用接入)、[翻译范围](#文案范围与覆盖)和[覆盖内置文案](#修改内置文案)。

## 应用接入

### 声明支持的语言

如果应用还没有自己的翻译目录，在创建窗口前添加：

```go
mygo.App.SetLanguages(nui.SupportedLocales()...)
```

`SupportedLocales()` 返回一份独立的 `[]string{"en", "zh-Hans"}`。如果应用已经通过 MyGo 的 `i18n.Register` 注册翻译目录，继续由应用声明支持的语言即可，**不要再对组件库的目录调用 `i18n.Register`**。

组件库使用 MyGo 的 `i18n.NewLibraryCatalog` 加载 `locales/`，命名空间为 `nuxtui`。每个组件从当前窗口的 `c.Locale()` 读取语言，不另外维护全局语言状态，也不会修改应用支持的语言列表。

### 切换语言

在按钮等 UI 动作中调用：

```go
mygo.App.SetLocale("zh-Hans") // 简体中文
mygo.App.SetLocale("en")      // 英文
mygo.App.SetLocale("")        // 跟随系统
```

上面是三种独立选择，实际操作时调用其中一种。MyGo 会刷新所有窗口、更新原生控件并保存偏好。启动时通常无需再强制设置语言：MyGo 会结合应用支持的语言、用户保存的选择和系统语言决定使用哪一种。

自动化测试可设置环境变量 `MYGO_LOCALE=en`，固定测试语言并避免保存测试中的语言选择。Gallery 通过 `mygo.App.SetLanguages("en")` 使用英文界面；需要中英文切换的应用可按上面的方式接入。

## 文案范围与覆盖

### 组件会自动翻译的内容

| 类型 | 例子 |
| --- | --- |
| 操作名称和辅助技术名称 | 清空、关闭、移除、取消、重试、上一页、下一页、增减数值 |
| 默认提示和状态 | 搜索、创建选项、加载中、空列表、空表格、上传状态和文件规则错误 |
| 内置输入错误 | 通用无效值、数字、日期和时间解析错误 |
| 日期展示与原生控件文案 | 日历年月和星期、ColorPicker 的通道名称、编辑器系统菜单 |

已经保存的内置错误会在切换语言后重新格式化；切换语言本身不算一次表单编辑。组件不会因此重置输入草稿、选区或业务值。

### 应用需要自行翻译的内容

显式传入的 `Label`、`Description`、`Placeholder`、`ErrorMessage`、`EmptyText`、`ChooseLabel`、`CloseLabel` 等文字保持原样。业务校验错误、服务端错误、Toast 标题、菜单项目、表格数据和 Timeline 日期也由应用处理。

上传规则产生的内置错误会继续随语言更新。如果应用改写了 `UploadFile.Error`，该值会作为业务文字保留。

### 几个容易混淆的默认文案

| 场景 | 文案与语言键 |
| --- | --- |
| 列表本身没有数据 | `noData`：No data / 没有数据 |
| 有查询词，但没有匹配项 | `noMatch`：No matching data / 没有匹配的数据 |
| PinInput 的默认辅助技术名称 | 文本模式用 `pinCharacters`，数字模式用 `pinDigits`；数量随 `Length` 变化 |
| 创建选择项、头像组剩余人数 | 分别使用 `createItem`、`morePeople` |

例如 5 格 PinInput 的默认名称为 `5 characters` / `5 个字符`；数字模式为 `5 digits` / `5 位数字`。这是编辑器的辅助技术名称，屏幕上每格的占位符仍由 `Placeholder` 决定。显式 `Label` 或 FormField 标签优先。

旧的空状态键 `noOptions`、`noResultsFound`、`noResults`、`noRecords`、`noItems` 仍保留；应用已经覆盖其中某个键时，对应组件继续使用该覆盖。枚举值、图标和分隔符，以及两种语言下相同的百分号，不单独建立翻译键。

## 修改内置文案

在**应用自己的 MyGo 翻译目录**中加入 `nuxtui.` 前缀的键，即可覆盖对应组件文案。例如：

应用的 `en.json`：

```json
{
  "@@locale": "en",
  "nuxtui.noMatch": "Nothing matched",
  "nuxtui.clearNamed": "Clear {name}"
}
```

应用的 `zh-Hans.json`：

```json
{
  "@@locale": "zh-Hans",
  "nuxtui.noMatch": "没有匹配的内容",
  "nuxtui.clearNamed": "清空{name}"
}
```

应用目录按 MyGo 的方式通过 `i18n.NewCatalog` 和 `i18n.Register` 接入。未覆盖的键使用组件库翻译；组件库尚不支持的语言回退到英文。

全部键见[英文目录](../locales/en.json)和[简体中文目录](../locales/zh-Hans.json)。修改带参数的文案时，保留参数名和类型，例如上例中的 `{name}`。数量变化使用 MyGo 支持的 ICU plural 规则处理。

## 格式与语言范围

### 日期和时间

Calendar 使用 MyGo 的日期格式化能力显示年月和星期。InputDate、InputTime 根据 MyGo 的 CLDR 区域格式排列日期或时间分段、选择分隔符，并显示对应语言的上下午文字。输入和显示的数字仍使用 ASCII 数字。

`DateInputState.Text` 始终保存 ISO 日期草稿；`TimeInputState.Text` 保存固定数字时间及 AM/PM 草稿。它们的存储格式与屏幕上的分段顺序分开处理，切换语言时保留业务值、草稿和字段焦点。每周从哪一天开始仍由应用通过 `WeekStart` 配置。

分段名称使用 `dateYear`、`dateMonth`、`dateDay`、`timeHour`、`timeMinute`、`timeSecond`、`timePeriod`；占位符使用这些名称加 `Placeholder` 后缀的键。

### 尚未覆盖的范围

目前未内置繁体中文、完整的地区数字输入和多历法。RTL 和屏幕阅读器的完整体验也尚未全面验证。平台支持与输入法问题见[兼容性说明](compatibility.md)。
